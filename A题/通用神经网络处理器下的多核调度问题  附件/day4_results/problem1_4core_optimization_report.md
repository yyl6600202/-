# 问题一 4 核平均加速比优化记录

本记录参考工作区的《两套模型说明与平均加速比优化方案》和 A 题模型计划，针对当前 4 核问题一实现做了定向候选搜索。历史材料中的论文均值只用于比较思路；本文数值来自当前附件数据和官方问题一评估器。

## 发现

原 100-case 4 核批处理对 `wide_shallow` 一律选择 `continuous`。这组共有 21 个 case，平均加速比只有 **1.3767×**，其中 17 个 case 比单核慢。其余类别表现较好：`high_spill_risk` 为 2.8999×，`mixed` 为 1.8604×，`deep_narrow` 按单核方案执行。

这说明当前主要瓶颈不是所有 case 的负载均衡，而是按图类别固定选择单一分区规则：同属宽浅图的 case，对连续切分和连通分量切分的响应差异很大。

## 优化办法

对 `wide_shallow` case 生成 `single`、`continuous`、`wave`、`aligned`、`components` 五类候选，用现有 `estimate_problem1_score` 排序，并由官方评估器计算候选 Makespan。始终把单核方案保留为 incumbent；最终只接受 Makespan 更小的方案，Makespan 相同再比较额外搬运量和子图数。

候选估分只负责排序，不能代替官方评估。`case_093/aligned` 就通过了结构校验，但官方评估器发现核心内调度与子图依赖形成环，因此被拒绝并从候选中排除。

对当前低分的非宽浅图也做了候选对照。13 个 case 中只有 `case_082` 和 `case_085` 有轻微改善，其余候选都没有降低 Makespan。因此这轮搜索预算优先放在宽浅组，符合按潜在平均分收益分配预算的建议。

## 实测结果

| 指标 | 原方案 | 定向候选方案 |
|---|---:|---:|
| 100-case 算术平均加速比 | 2.2703× | **2.5497×** |
| 几何平均加速比 | — | 2.2873× |
| 中位数 | — | 2.6338× |
| 比单核快的 case | 67 | 84 |
| 与单核持平的 case | 16 | 16 |
| 比单核慢的 case | 17 | **0** |
| 单核总周期 | 312,479,373 | 312,479,373 |
| 问题一总周期 | 108,277,776 | 106,532,887 |

宽浅组的平均加速比从 **1.3767×** 提升到 **2.7063×**。在 21 个宽浅 case 上，只取估分前两名候选并按官方 Makespan 选优，结果与五类候选全量对照的最优 Makespan **21/21 相同**。把同一 shortlist 用在全部 34 个已扫描 case 时，只有 26/34 命中全量候选最优；额外保留单核 incumbent 后为 30/34。因此，当前证据支持把“估分前两名 + 官方评估”优先用于宽浅图，其他类别继续用现有规则或完整候选搜索。

将 34 个已扫描 case 的全量候选最优与其余 66 个 case 的原 incumbent 合并后，100-case 算术平均增加 **0.2793×**，相对提升约 **12.3%**。20 个 case 的加速比实际提高，80 个保持不变，没有 case 退化。

非宽浅低分组的搜索只把 100-case 均值额外提高约 **0.0001×**，所以本轮的主要收益明确来自宽浅组的候选选择。

## 结果范围与后续

这份 2.5497× 是 4 核定向优化结果：34 个 case（全部 21 个宽浅图及 13 个低分非宽浅图）从官方候选对照中取优，其余 case 保留原 incumbent。它不是 100 个 case 全部穷举五类规则后的理论最优值，也不替代题目要求的 2、3、5 核结果。

下一步应把宽浅图的候选筛选策略在 2、3、5 核分别验证；对混合图和高 spill 图继续沿用当前规则，只有当便宜代理显示有分数空间时才增加官方候选评估。每个核数独立保存单核基准和逐 case incumbent，最终平均值按 100 个逐 case 加速比的算术平均计算。
